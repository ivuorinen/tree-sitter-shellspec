# mise consolidation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `mise.toml` pins every toolchain and defines every development command as a mise task, and CI runs those
same tasks.

**Architecture:** `mise.toml` holds `[settings]`, `[tools]` and the one- or two-line tasks. Multi-line scripts become
executable bash file tasks under `.mise/tasks/`, named by path (`.mise/tasks/check/generated` is `check:generated`).
Workflows call `mise run <task>` through `jdx/mise-action`. The npm dev scripts and the `tree-sitter-cli` devDependency
are removed in one cut-over task, together with every hook, rule, skill and doc that names them.

**Tech Stack:** mise 2026.10.x (tasks, `mise.lock`), tree-sitter CLI 0.27.1 (`aqua:tree-sitter/tree-sitter`), Node,
Python, Go, Rust, prek, GitHub Actions with `jdx/mise-action`.

**Spec:** `docs/superpowers/specs/2026-10-21-mise-consolidation-design.md`

## Global Constraints

- Tool pins, verbatim: `node = "24.22.1"`, `python = "3.14.8"`, `rust = "1.99.0"`, `tree-sitter = "0.27.1"`,
  `prek = "0.5.6"`, `"npm:mega-linter-runner" = "10.1.0"`. Go is not listed; it comes from `go.mod`'s `toolchain` line.
- `[settings]`: `idiomatic_version_file_enable_tools = ["go"]` and `lockfile = true`; `mise.lock` is committed.
- File tasks are executable bash with `#!/usr/bin/env bash`, `set -euo pipefail`, and a `#MISE description="…"` line.
- Scratch output goes under `.temp/` (already gitignored). `.gitignore` does not change.
- `install: node-gyp-build` stays in `package.json` `scripts`. `Makefile`, `CMakeLists.txt`, `pyproject.toml`,
  `setup.py`, `go.mod`, `Cargo.toml` do not change.
- `docs/superpowers/` (other than this plan and its spec) and `docs/audit/` are historical and are not edited.
- CI: `MISE_VERSION: v2026.10.8` as a workflow-level env with `# renovate: datasource=github-releases depName=jdx/mise`;
  `jdx/mise-action@08ae2a091c038e1e05ec6f5115dc5c69d5a2a6b8 # v5.1.2` with `version: ${{ env.MISE_VERSION }}`.
- Release jobs set `cache: false` on mise-action.
- `.editorconfig`: 2-space indent, LF, final newline, no trailing whitespace outside Markdown, 160-character lines.
- Never edit `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` or lockfiles by hand.
  `package-lock.json` changes only through `npm uninstall`.
- Git: stage explicit paths only, check `git status --short` before committing, no attribution trailers. Run
  `git commit` only after the user has said to commit, either per step or once for the whole plan.

## Review Focus

Most likely first:

- Node 22 leg: `MISE_NODE_VERSION=22` names a version that `mise.lock` does not hold. The `test` job must still
  install node 22 and pass; Task 4 adds the local check `MISE_NODE_VERSION=22 mise exec -- node --version`.
- A fresh CI runner has no global mise config and no `mise trust`. `go version` there must report go1.27.3 (from
  `go.mod`), and the project `mise.toml` must load. Task 1 checks Go with the global config bypassed; the PR's CI
  checks trust.
- A local run of `test:bindings:node` must not leave `node_modules/tree-sitter` behind, and a second run must not fail
  on an existing link. Task 3 runs it twice and checks the link is gone afterwards.
- Hooks after the cut-over: `npx tree-sitter generate`, which used to be allowed, is now blocked, while
  `mise run generate` and `mise run rebuild` pass. Task 6 feeds each command to the guard.
- `mise run generate` run by `post-edit-lint.sh` in a shell that never activated mise: the hook calls `mise` by name,
  so it needs mise on PATH, not activation. Task 6 runs the hook with a minimal PATH.
